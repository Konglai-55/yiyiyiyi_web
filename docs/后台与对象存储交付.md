# 新闻后台与对象存储交付

## 现在怎么存

| 内容 | 保存位置 |
| --- | --- |
| 图片和视频 | 原有 Rain3 桶 yiyiyiyi，website/ 公开外链，地址不变 |
| 新闻正文 包括草稿和下架文章 | 独立私有桶 `yiyiyiyicms-private` 的 `cms-private/news-v1/catalog.json`，仅服务端签名读取 |
| 修改前的新闻备份 | 私有桶 `cms-private/news-v1/history/`，每次修改先备份再提交 |
| 登录会话 密码覆盖项 限流 访问统计 | Node 生产环境的 ADMIN_DATA_DIR/admin.sqlite |
| Wrangler 本地 Cloudflare 调试 | 原 DB 绑定继续保存登录与统计，新闻仍走对象存储 |

新闻量较少，使用一个有版本号的 JSON 目录保存全部文章，避免分别更新“文章”和“列表”时不一致。目录最大 16 MB，不适合作为大规模内容系统。历史快照逐次增加，需定期备份并按业务保留期限人工清理；当前没有自动删除历史记录。

访客访问本站 /news 和 /news/文章地址，由服务器读取私有 JSON 并输出完整网页。不会把草稿 JSON 交给浏览器，也不会将访问密钥打包进客户端。每次读取不使用持久缓存；下架、删除及未来发布日期由服务端筛选。存储不可用时请求失败，不会恢复代码里的旧文章。

保存使用 S3 If-Match 与文章版本号校验。两人改同一篇，后提交者收到冲突提示；改不同文章会重新读取并合并。删除再创建同名地址仍递增版本，旧窗口不能覆盖新文章。备份写失败则拒绝修改。网络中断导致结果不确定时，先刷新文章确认，不要重复新建。

## DreamPanel 部署

1. Node 22.13 或更高版本，建议使用 Node 24 LTS。项目未新增数据库服务或原生 npm 扩展，使用 Node 内置 SQLite。
2. 构建命令仍是 npm run build；启动命令仍是 npm start，对应 vinext start --port ${PORT:-3800}，监听 0.0.0.0。
3. 在面板配置 .env.example 中的变量。S3 与管理员密钥沿用已有值，不能提交到仓库，不能放入 NEXT_PUBLIC_ / VITE_ 变量。
4. ADMIN_DATA_DIR 必须是绝对路径，例如 /var/lib/yixiao-admin；创建并挂载持久目录，授予运行用户读写权限。不要指向每次发版都会替换的代码目录，不能放在 public 下。未配置时后台明确报错，不会静默写临时目录。
5. APP_ORIGIN 设置为真实网站来源 https://yiyiyiyi.xn--fiqs8s，不带尾部斜杠。它用于 CSRF 检查及 HTTPS Secure Cookie，避免反向代理内部 HTTP 地址造成登录失败。
6. 如 nginx 已覆盖 X-Real-IP 且应用端口不允许公网绕过代理，设置 TRUST_PROXY=1，按真实来源限流。否则保留 0，登录请求共用保守限额，不信任用户伪造的 IP 头。
7. 官网图片仍放原来的 `website/` 公开桶；新闻正文和历史版本放独立的 `yiyiyiyicms-private` 私有桶。私有桶必须匿名不可读、不可列举。代码会以无敏感内容的临时对象测试隐私与条件写，失败就拒绝写新闻。
8. 当前设计面向单台服务器。可在同机使用同一 SQLite 路径，但不要让多台服务器使用各自独立文件冒充共享统计；横向扩容时另迁登录与统计到共享数据库。

首次切换新闻桶时，先同时配置旧桶的 `S3_*` 和新桶的 `NEWS_S3_*`，运行 `node --env-file=.dev.vars scripts/migrate-news-storage.mjs`。脚本只复制 `cms-private/news-v1/`，不会删除旧数据；确认新桶校验通过后，再移除旧桶凭据。

生产系统可通过部署环境或忽略的 .env.production 提供变量。vinext start 不自动读取 Wrangler 的 .dev.vars。测试脚本使用 node --env-file=.dev.vars 显式加载本地配置；该文件不要上传公开仓库。

## 已有新闻迁移

初始化仅允许“目标不存在时创建”。再次执行会保留现有目录，不覆盖线上编辑。

```sh
# 先验证当前存储；仅写入并删除随机测试对象
node --env-file=.dev.vars scripts/check-news-storage.mjs

# 推荐：从原 D1 的 SQLite 快照导入，保留所有发布状态与版本
node --env-file=.dev.vars scripts/init-news-storage.mjs --sqlite /path/to/legacy.sqlite

# 也可以使用包含完整 ManagedArticle 记录的 JSON 导出
node --env-file=.dev.vars scripts/init-news-storage.mjs --json /path/to/news-export.json

# 只有确认没有旧后台数据时才使用这项，明确导入代码中的五篇文章
node --env-file=.dev.vars scripts/init-news-storage.mjs --bundled
```

本次已从本机旧 D1 导入 5 篇已发布文章到正式私有前缀，原 D1 文件未删除，源快照留在 .private/news-migration/。本机 D1 数据不等于线上 D1 数据；如线上另有编辑内容，先导出对照，不要用本机数据覆盖。生产部署使用默认前缀即可读取已迁入的目录，无需再次初始化。

旧登录与统计可另外迁移，目标原有记录优先保留，旧登录令牌不迁移：

```sh
ADMIN_DATA_DIR=/var/lib/yixiao-admin node --env-file=.dev.vars scripts/migrate-admin-state.mjs /path/to/legacy.sqlite
```

本机已备份并迁入原有 13 条本地浏览记录，不代表线上真实流量。旧管理员密码保持不变；首次 Node 运行从 ADMIN_PASSWORD_HASH 验证，若迁入了 settings 中的密码覆盖项，该项优先。

## 备份与恢复

- 新闻每次成功变更前保存私有历史快照。误删恢复由维护人员从快照提取目标文章，经后台重新创建；不要直接整体覆盖 catalog.json，否则可能覆盖后续编辑。后台“永久删除”是从活动列表删除，私有历史备份仍保留。
- SQLite 备份使用下面的命令。不要在运行中只复制 admin.sqlite，WAL 中可能还有未合并数据。

```sh
ADMIN_DATA_DIR=/var/lib/yixiao-admin node scripts/backup-admin-state.mjs
```

- 为持久卷及新闻备份另做异地备份。示例命令不等于已经配置定时备份。
- SQLite 恢复应先停止应用，备份现有目录，再将一致性快照放回持久目录，处理旧 WAL/SHM 文件，检查权限后启动；操作前由维护人员核对路径。密码遗失时重新生成密码哈希，更新配置并清除旧覆盖项与会话。

## 客户操作与统计

客户继续在 /admin 登录，使用原来的新建、编辑、封面上传、草稿、发布、下架、删除与预览，无需操作对象存储。未来日期按北京时间到当日才公开。

访问统计保留 90 天，记录 PV、标签页会话、今日浏览量、页面排行、每日趋势、设备和来源域名。会话随机标识经 HMAC 后保存，不保存原始 IP；尊重 DNT/GPC，排除后台和常见爬虫。它是基础浏览记录，不是精准人数或计费依据。

## 验收命令

```sh
TEST_ORIGIN=http://127.0.0.1:3800 node scripts/verify-admin.mjs
node --env-file=.dev.vars scripts/verify-news-storage.mjs
TEST_ORIGIN=http://127.0.0.1:3800 node scripts/verify-admin-restart.mjs prepare
# 重启同一个持久目录的应用后
TEST_ORIGIN=http://127.0.0.1:3800 node scripts/verify-admin-restart.mjs check
```

verify-admin 从本地私有交付文件读取密码，也支持 TEST_ADMIN_PASSWORD。verify-news-storage 使用独立的随机私有前缀，验证并发、下架、未来发布、备份失败、故障不回退以及删除重建版本保护，结束后删除其测试对象。重启测试会新建不公开草稿，check 完成后删除。只对获准的测试实例运行，不把账号密码打印到日志。
